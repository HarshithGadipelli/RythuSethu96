================================================================================
1. EXECUTIVE SUMMARY & PLATFORM VISION
================================================================================
Rythu Sethu (రైతు సేతు / किसान सेतु / "Farmer's Bridge") is a decentralized, full-stack, enterprise-grade agricultural trade and logistics platform. Built to eliminate exploitative agricultural middlemen, Rythu Sethu empowers marginal, smallholder, and progressive commercial farmers by connecting them directly with consumers, institutional buyers, and decentralized logistics agents.

The platform orchestrates complex agricultural commerce across four distinct authenticated user roles:
1. Farmers: Publish live harvest inventory, track lifecycle stages (Seeding, Growing, Harvested), receive AI-powered dynamic pricing and agro-climatic crop recommendations, access cold storage clearance liquidation, and manage farm-tour agritourism.
2. Customers: Browse farm-fresh produce with verified farmer Trust Badges, execute single or multi-location checkout (dispatching different basket items to friends/family in distinct locations within a single order), track real-time agent GPS delivery on Leaflet maps, and access community group buying.
3. Logistics Agents: Receive automated route assignments, navigate delivery routes optimized via a Dabbawala-style hub-and-spoke Travelling Salesperson Problem (TSP) heuristic algorithm, utilize multi-modal Gemini Vision for proof-of-delivery verification, and monitor SLA countdowns.
4. Platform Administrators: Supervise financial ledgers and escrow releases, analyze real-time market demand and velocity tensors, broadcast push advisories to farmers (e.g., anti-crop burning, millet promotion), and liquidate perishable clearance stock through central cold storage.

4.1 BACKEND TIER (`/backend`):
- `server.js`: Master application bootstrap. Binds Express to native HTTP server, initializes Socket.io with open CORS, connects to MongoDB, mounts security middleware stack (Helmet, rate-limiting, NoSQL sanitization, DOMPurify), registers 22 REST route modules, configures static uploads with cache-invalidation headers, and sets up real-time socket events (`join_agent_room`, `agent_location_update`, `admin_broadcast`).

- `/backend/config/`:
  * `db.js`: Mongoose connection manager. Establishes TCP connection pool to MongoDB (local or Atlas) with auto-reconnection listeners (`error`, `disconnected`, `reconnected`).

- `/backend/models/` (28 Mongoose Data Schemas):
  * `User.js`: Unified polymorphic user schema. Stores authentication credentials (`email`, `phone`, `password` hashed with bcrypt), `role` enum (`farmer`, `customer`, `agent`, `admin`), `geoPosition` (GeoJSON Point with `2dsphere` index for spatial queries), `walletBalance`, `rewardPoints`, embedded sub-profiles (`farmerProfile`, `customerProfile`, `agentProfile`), and trust ratings.
  * `Crop.js`: Farmer inventory entity. Tracks `name`, `category`, `price`, `quantity`, `unit` (kg, quintal, bag), `lifecycleStage` (`seeding`, `vegetative`, `harvesting`, `ready_to_sell`), `isOrganic`, `shelfLifeDays`, `harvestDate`, `images`, `isAdminStock` (Clearance liquidation flag), `originalFarmer`, `clearanceDiscount`, `coldStorageLocation`, and text index on crop name.
  * `Order.js`: Core transaction schema. Holds references to `customer`, `farmer`, `crop`, `quantity`, `totalAmount`, `status` (`pending`, `confirmed`, `assigned`, `picked_up`, `delivered`, `cancelled`), `escrowStatus` (`held`, `released`, `refunded`), `multiLocationGroupId` (linking multi-drop items), `deliveryAddress`, and payment references.
  * `Delivery.js`: Logistics execution schema. Stores `order`, `agent`, `status` (`assigned`, `in_transit`, `delivered`), `agentLatitude`, `agentLongitude`, `lastLocationUpdate`, `dropoffs` subdocument array (coordinates, addresses, drop status for multi-location runs), `optimizedRoute` path coordinates, and `estimatedDeliveryTime`.
  * `Block.js`: Cryptographic ledger block schema. Stores `index`, `timestamp`, `transactions` array (order payloads), `previousHash`, and `hash` (SHA-256). Ensures transaction immutability.
  * `Demand.js`: Region-specific demand metrics. Stores `cropName`, `region`, `demandScore`, `velocityScore`, `searchCount`, `orderCount`, and timestamp.
  * `SearchHistory.js`: Marketplace query audit log. Stores `query`, `category`, `user`, `coordinates`, and `timestamp` with a 30-day Time-To-Live (TTL) index.
  * `Review.js`: Post-delivery customer rating and review schema. Stores `order`, `crop`, `farmer`, `customer`, `rating` (1-5), `comment`, `sentimentScore` (computed via Gemini NLP), and `isVerifiedPurchase`.

  * `Customer.js`: Customer preference schema (favorite crops, default delivery addresses, dietary preferences).
  * `Agent.js`: Logistics agent operational profile (vehicle type [bike, truck, van], license number, current shift status, active deliveries, SLA score).
  * `Admin.js`: System administrator credentials, audit logs, and operational privilege flags.
  * `Cart.js`: Server-side persistent customer cart schema.
  * `Auction.js`: Live B2B crop auction schema (starting bid, current highest bid, reserve price, bid history, expiry timer).
  * `BoxSubscription.js`: Recurring curated vegetable/fruit box subscription schema (weekly, bi-weekly, monthly plans).
  * `Subscription.js`: General farmer/customer recurring platform service subscriptions.
  * `CropRequest.js`: B2B customer custom demand request for unlisted crops.
  * `Farm.js`: Farm geolocation, acreage, and agritourism infrastructure profile.
  * `FarmTourBooking.js`: Agritourism physical tour reservation schema (visitor count, date, status, payment status).
  * `GlobalConfig.js`: Dynamic platform runtime settings (commission percentage, base delivery fee, per-km rate).
  * `Group.js`: Community group-buying pools for collective wholesale discounts.
  * `Notification.js`: User notifications with read/unread tracking and push metadata.
  * `Payment.js`: Escrow payment tracking schema (Razorpay order ID, payment ID, signature, status).
  * `Policy.js`: Government and platform agricultural subsidies, crop insurance, and policy advisories.
  * `Prediction.js`: Cached machine learning outputs (price trends, yield predictions).
  * `SoilTestRequest.js`: Farmer soil laboratory testing requests (NPK levels, pH, micronutrients, AI advisory).
  * `Ticket.js`: User dispute and customer service support tickets.
  * `AILog.js`: Audit logging for Gemini and ML inference latencies, tokens, and errors.

5. DEEP DIVE: MATHEMATICS, ALGORITHMS, MACHINE LEARNING & CRYPTOGRAPHY

5.1 THE HAVERSINE SPHERICAL DISTANCE FORMULA
Calculates the great-circle distance between two geographic coordinates on a spherical Earth model:
- Formula:
  Δlat = (lat2 - lat1) * π / 180
  Δlon = (lon2 - lon1) * π / 180
  a = sin²(Δlat / 2) + cos(lat1 * π / 180) * cos(lat2 * π / 180) * sin²(Δlon / 2)
  c = 2 * atan2(√a, √(1 - a))
  Distance (km) = R * c   [where R = 6371 km]
- Time Complexity: O(1) per coordinate pair.
- Database Integration: Complemented by MongoDB `2dsphere` indexes on `User.geoPosition` enabling O(log N) geospatial spherical filtering.

5.2 OSRM DRIVING DISTANCE MATRIX API
To account for actual road networks, rivers, and traffic geometries, the system queries the Open Source Routing Machine (OSRM) Table API:
- Endpoint: `http://router.project-osrm.org/table/v1/driving/{lon1,lat1;lon2,lat2;...}?annotations=distance`
- Returns an N x N matrix of real driving distances in meters.
- Fallback: Automatically falls back to the Haversine formula if the external network is unreachable.

5.3 DABBAWALA-STYLE ZONE CLUSTERING & NEAREST-NEIGHBOR TSP HEURISTIC
Multi-location agricultural deliveries present an NP-hard Travelling Salesperson Problem with pickup-before-delivery precedence constraints.
- Step 1: Spatial Grid Binning (Dabbawala Concept):
  Each coordinate is mapped to an approximate 2km geographic zone:
  ZoneID = `${floor(lat * 50)}_${floor(lon * 50)}`
- Step 2: Constrained Nearest-Neighbor Traversal:
  Starting from the agent's current location, the algorithm prioritizes tasks in the *same* zone before moving across zones.
  Precedence Rule: A `delivery` dropoff cannot be visited until its corresponding `pickup` has been added to `completedPickups`.
- Time Complexity: O(N²) where N is the number of delivery stops (typically N < 25 per agent run).

5.4 RANDOM FOREST REGRESSION (PRICE & DEMAND)
The core predictive engine uses an ensemble of B decorrelated decision trees:
- Output Prediction: ŷ = (1 / B) * Σ f_b(x)
- Tree Induction: Uses bootstrap aggregation (bagging) with random feature subsampling at each split to minimize variance without increasing bias.
- Evaluation Metrics: Mean Squared Error (MSE) and Coefficient of Determination (R² ~ 0.85).

5.5 XGBOOST GRADIENT BOOSTING (ELASTIC DYNAMIC PRICING)
Optimizes fair agricultural pricing by minimizing an objective function containing training loss and model complexity penalties:
- Obj = Σ L(y_i, ŷ_i) + Σ [γ T_m + (1/2) λ ||w_m||²]
- Utilizes second-order Taylor expansion to approximate the loss function, enabling fast convergence across market supply elasticity features.

5.6 APRIORI ASSOCIATION RULE MINING (MARKET BASKET ANALYSIS)
Identifies cross-selling combinations (e.g., "Customer buying Tomatoes also buys Onions") from historical transaction logs:
- Support(A) = Frequency(A) / Total_Orders
- Confidence(A -> B) = Support(A ∪ B) / Support(A)
- Lift(A -> B) = Confidence(A -> B) / Support(B)
- Thresholds: Minimum Support = 0.05, Minimum Confidence = 0.60. A Lift > 1.0 indicates a statistically significant positive correlation.

5.7 MULTI-FACTOR 10-PARAMETER FARMER TRUST SCORE FORMULATION
Computes an objective, tamper-proof score (0 to 100) determining badge status:
  TrustScore = Σ (Weight_i * Points_i)
  Parameters:
  1. Verification Status (Aadhaar KYC): Weight 10% (10 pts)
  2. Average Customer Review Rating: Weight 20% (20 pts, normalized from 1-5 scale)
  3. Order Fulfillment Rate: Weight 15% (15 pts, fulfilled / accepted orders)
  4. Farming Experience: Weight 5% (5 pts, capped at 10+ years)
  5. Organic Certification: Weight 10% (10 pts)
  6. Total Sales Volume: Weight 10% (10 pts, scaled logarithmically)
  7. Account Age / Platform Tenure: Weight 5% (5 pts)
  8. Profile Completeness: Weight 10% (10 pts)
  9. Customer Response Rate: Weight 5% (5 pts)
  10. Low Return / Dispute Rate: Weight 10% (10 pts)
  Grade Classification:
  - 90 - 100: 🏆 Platinum ("Exceptional")
  - 75 - 89:  🥇 Gold ("Highly Trusted")
  - 60 - 74:  🥈 Silver ("Trusted")
  - 40 - 59:  🥉 Bronze ("Building Trust")
  - 0 - 39:   🌱 New ("Getting Started")

5.8 REAL-TIME DEMAND VELOCITY TENSOR ALGORITHM
Calculates live product demand velocity using a non-linear velocity score:
  VelocityScore = [1.5 * TotalSold] + [2.5 * (OrderCount^1.2)] + [0.05 * Revenue]
  Multipliers:
  - Deep Seasonality Multiplier: 2.5x boost for biological seasonal crops.
  - Weekend Perishable Multiplier: 1.5x boost on Saturdays and Sundays for fresh kitchen staples.

5.9 AGRO-CLIMATIC ZONE CLASSIFICATION & LIVE WEATHER SUITABILITY SCORING
Replaces arbitrary seasonal filters with a meteorological engine:
- Live Telemetry: Fetches exact current temperature, relative humidity, surface precipitation, and wind speed via Open-Meteo.
- Agro-Climatic Zone Mapping:
  * Hot Arid (Rajasthan, North Gujarat): Temp > 32°C, Humidity < 40%, Rainfall < 2mm
  * Tropical Humid (Kerala, Coastal Karnataka, Konkan): Temp > 24°C, Humidity > 75%, Rainfall > 5mm
  * Sub-Tropical Continental (Punjab, Haryana, UP, MP): Seasonal extremes
  * Temperate Highland (Himachal Pradesh, J&K, Uttarakhand): Lat > 30°N, Temp < 18°C
  * Coastal Maritime (TN, Andhra, Odisha, Bengal coasts): Humidity 65-85%, moderate rainfall
- Bell-Curve Weather Suitability Scoring:
  Score = 100 - (|T_current - T_ideal| * W_temp) - (|H_current - H_ideal| * W_humidity) - RainPenalty
  Bonus: +8% promotion incentive for drought-resistant Millets (Ragi, Jowar, Bajra).

5.10 CRYPTOGRAPHIC BLOCKCHAIN LEDGER SIMULATION
Provides immutable provenance for every completed transaction:
- Block Structure: { Index, Timestamp, Transactions: [OrderPayload], PreviousHash, Hash }
- Hash Function: SHA-256 (Secure Hash Algorithm 256-bit)
- Block Invalidation: Tampering with any historical order modifies that block's hash, breaking the cryptographic chain (`block[i].previousHash !== block[i-1].hash`).

5.11 WEB AUDIO API PROCEDURAL ACOUSTIC SYNTHESIZER
Generates a living acoustic soundscape directly inside the browser without downloading heavy audio files:
- Birdsong Generation: Randomly triggered OscillatorNodes sweeping high-frequency exponential ramps (2600 Hz - 3800 Hz) shaped by rapid attack/decay GainNodes.
- Cricket Night Chorus: White noise audio buffers passed through resonant BiquadFilterNodes (bandpass at 4500 Hz) modulated at 12 Hz.
- Krishna Bansuri Flute: Web Audio synthesis reproducing peaceful Indian Raag Bhupali melodies.

5.12 MULTILINGUAL PHONETIC INTENT PARSER
A specialized natural language tokenizer supporting rural Indian agricultural vocabulary:
- Mappings: Cross-maps hundreds of colloquial crop names across Telugu (టమోటా, ఉల్లిపాయ, వరి), Hindi (टमाटर, प्याज, चावल), English, Tamil, and Kannada to canonical entities.
- Unit Parser: Recognizes rural metrics: "biyyam 5 bastalu" -> `{ crop: "Rice", quantity: 5, unit: "bag" }`.

5.13 GOOGLE GEMINI 1.5 FLASH MULTI-MODAL VISION & NLP CASCADE
- Visual Proof of Delivery: Delivery agent captures a photo of the handed-over produce. Gemini 1.5 Flash compares the visual features of the delivery photo against the marketplace listing image to verify produce authenticity and prevent delivery fraud.
- Dynamic Nutrition Synthesis: If a rare indigenous crop lacks pre-computed nutrition facts, Gemini acts as an API, synthesizing standard macro-nutrients into validated JSON schemas.

6. REAL-TIME EVENT ARCHITECTURE (SOCKET.IO) & END-TO-END WORKFLOWS
================================================================================

6.1 SOCKET.IO CHANNEL TOPOLOGY & EVENT MATRIX
The system maintains persistent, full-duplex WebSocket connections with the following event architecture:
- Connection Lifecycle:
  * Client connects -> `connection` event fired -> client receives socket ID.
  * Agent authentication -> client emits `join_agent_room(agentId)` -> server binds connection to room `agent_${agentId}`.
- Operational Events:
  * `order_created`: Broadcast to all active logistics agents when a customer checks out.
  * `agent_location_update`: Emitted by agent's mobile browser with GPS `{ agentId, lat, lng }`.
  * `agent_location_changed`: Broadcast to customer tracking room and admin global map.
  * `admin_broadcast`: Dispatched by Admin -> server emits `admin_broadcast_received` to all connected farmer sockets.
  * `disconnect`: Connection cleanup.

6.2 END-TO-END MULTI-LOCATION ORDER & ESCROW LIFECYCLE
1. Product Discovery: Customer navigates `Marketplace.jsx`. Search triggers debounced logging to `SearchHistory`. Customer adds produce to cart.
2. Multi-Location Allocation: In `CartSidebar.jsx`, customer toggles Multi-Location delivery. Item 1 is allocated to "Home Address", Item 2 to "Parents Address".
3. Checkout & Payment: Customer submits order. Backend `/api/orders/create-multi` verifies stock, calculates distance-based delivery charges, initiates Razorpay Escrow payment, creates linked `Order` records, and appends the transaction to the SHA-256 `Block` ledger.
4. Agent Radial Assignment: The backend invokes `autoAssignMultiDelivery()`. Using MongoDB `2dsphere` spatial indexing, nearby available agents within 15km are queried. An agent is assigned, and a `Delivery` record is created containing the multi-stop `dropoffs` array.
5. Real-Time Dispatch: Socket event `order_created` updates the assigned agent's `AgentDashboard.jsx`.
6. Route Execution: Agent clicks "Optimize Route". The Dabbawala TSP heuristic orders pickups and deliveries into a minimal-mileage sequence.
7. Verification & Escrow Release: At delivery, the agent uploads a photo. Gemini 1.5 Flash validates the produce. The order shifts to `delivered`. The backend releases the escrowed funds directly to the farmer's wallet. Customer is prompted for a review.

7. CYBERSECURITY DEFENSE ARCHITECTURE & OWASP TOP 10 MITIGATION
================================================================================
Rythu Sethu incorporates defense-in-depth security mitigations:

1. A01:2021 - Broken Access Control:
   - Enforced by `authMiddleware.js` and `roleMiddleware.js`. Endpoints verify both cryptographic JWT signatures and role claims (`adminOnly`, `farmerOnly`, `agentOnly`). Users cannot access or modify resources belonging to other tenants.

2. A02:2021 - Cryptographic Failures:
   - Passwords hashed using Bcrypt with 10 salt rounds.
   - JWT tokens signed with high-entropy `JWT_SECRET` using HMAC-SHA256.
   - All transactions immutably linked in SHA-256 blockchain blocks.

3. A03:2021 - Injection (NoSQL & XSS):
   - NoSQL Injection: Neutralized by `express-mongo-sanitize`, which recursively deletes any keys starting with `$` or containing `.` from incoming payloads.
   - Cross-Site Scripting (XSS): Defended by a custom `sanitizeMiddleware.js` combining DOMPurify and JSDOM, stripping malicious `<script>`, `onerror`, and HTML injection vectors prior to Mongoose processing.

4. A04:2021 - Insecure Design:
   - Financial transactions utilize an Escrow state machine. Farmers cannot withdraw funds until visual proof-of-delivery is established or confirmed by the customer.

5. A05:2021 - Security Misconfiguration:
   - Helmet sets strict security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Strict-Transport-Security` (HSTS), and strips `X-Powered-By: Express`.

6. A07:2021 - Identification & Authentication Failures:
   - Sliding-window rate limiter (`express-rate-limit`) restricts clients to 1000 requests per 15 minutes, neutralizing brute-force credential stuffing.

13. EXHAUSTIVE REST API ENDPOINT REFERENCE (ALL 22 MODULES)
================================================================================
Every route registered on the Express application (`server.js`) maps to strict controller functions guarded by authentication and RBAC middleware chains:

1. Authentication & Onboarding (`/api/auth`):
   - `POST /register`: Registers user. Encrypts password using Bcrypt (10 rounds). Stores GPS `geoPosition` as GeoJSON Point. Returns user entity + signed JWT.
   - `POST /login`: Authenticates email/phone and password. Validates Bcrypt hash. Issues JWT containing `{ id, role }`.
   - `GET /me`: Returns profile of authenticated user from `req.user`. Requires `authMiddleware`.
   - `PUT /profile`: Updates user metadata (name, address, profile photo, vehicle details).
   - `POST /logout`: Client-side token invalidation.

2. Farmer Cockpit (`/api/farmer` & `/api/farmers`):
   - `GET /dashboard`: Aggregates active listings, pending orders, completed deliveries, and escrow wallet balance.
   - `GET /inventory`: Lists all crops owned by the logged-in farmer with lifecycle stages and clearance flags.
   - `GET /analytics`: Computes historical revenue curves, month-over-month yield growth, and top-selling produce.
   - `GET /financials`: Retrieves ledger of all settled and held escrow transactions.
   - `GET /leaderboard`: Public gamified ranking of farmers by Trust Score and verified organic acres.

3. Crop Catalog & Inventory (`/api/crops`):
   - `GET /`: Retrieves marketplace crops. Supports query parameters (`?category=`, `?search=`, `?lat=&lng=&radius=`, `?organic=true`, `?sort=price_asc|trust_desc`).
   - `GET /:id`: Retrieves single crop document with farmer profile, reviews, and nutritional breakdown.
   - `POST /add`: Creates new crop entity. Handles multipart image uploads via Multer. Enforces `farmerOnly` middleware.
   - `PUT /:id`: Updates crop price, available stock, or lifecycle updates (`sowing` -> `harvested`).
   - `DELETE /:id`: Sets `isLive: false` or deletes crop document.
   - `PUT /:id/sell-to-admin`: End-of-Day liquidation. Transcribes crop to admin ownership (`isAdminStock: true`), tags `originalFarmer`, applies 40% discount, and allocates to central cold storage.
   - `GET /category/:category`: Filters crops by category enum.

4. Transaction & Multi-Location Orders (`/api/orders`):
   - `POST /create`: Single checkout order creation. Deducts crop stock atomically. Generates 6-digit OTP verification code and bill number. Appends transaction to SHA-256 blockchain ledger.
   - `POST /create-multi`: Multi-location delivery checkout. Groups multiple items with custom delivery coordinates under a single `multiLocationGroupId`. Runs geospatial 2dsphere queries to auto-assign nearest logistics agent.
   - `GET /customer/:id`: Retrieves order history for a specific customer.
   - `GET /farmer/:id`: Retrieves incoming and completed orders for a farmer.
   - `GET /:id`: Retrieves detailed order record including timeline, tracking code, and product snapshot.
   - `PUT /:id/status`: Updates order state machine (`pending` -> `confirmed` -> `assigned` -> `picked_up` -> `delivered`).
   - `PUT /:id/verify-agent`: Resolves agent product mismatch report.

5. Decentralized Logistics (`/api/delivery`):
   - `GET /agent/:id/tasks`: Retrieves assigned deliveries for a logistics agent.
   - `POST /optimize-route`: Invokes Dabbawala-style TSP heuristic. Calls OSRM Table API to fetch road driving distance matrix, clusters stops into 2km zones, and returns optimized waypoint sequence.
   - `PUT /location`: Ingests live agent GPS telemetry and updates MongoDB `Delivery` document.
   - `PUT /update-status`: Progresses delivery status (`assigned` -> `in_transit` -> `delivered`).
   - `POST /verify-photo`: Uploads delivery photo to Gemini 1.5 Flash for visual verification against original crop photo.
   - `GET /track/:orderId`: Live tracking endpoint for customers, returning agent coordinates and ETA.

6. Administrator Control Suite (`/api/admin`):
   - `GET /analytics`: System-wide aggregate sales, GMV, platform commission revenue, and active user distribution.
   - `GET /users`: Paginated user list with role filters and KYC status.
   - `PUT /verify-user/:id`: Approves or rejects farmer Aadhaar KYC and organic certifications.
   - `GET /demand-prediction`: Returns regional demand velocity scores and over/undersupplied crop lists.
   - `POST /broadcast`: Broadcasts push notification and WebSocket alert to all online farmers (Millets, Anti-Burning, Weather).
   - `GET /clearance`: Lists all liquidated cold storage clearance crops.
   - `PUT /clearance/:id/price`: Adjusts resale markdown price for clearance stock.

7. Machine Learning & Forecasting Gateway (`/api/ml`):
   - `GET /seasonal-prediction`: Fetches live weather telemetry from Open-Meteo, classifies agro-climatic zone, and returns scored crop recommendations (0-100%).
   - `POST /suggest-crop`: Evaluates soil pH, temperature, and rainfall inputs to predict optimal crop.
   - `POST /predict-demand`: Forecasts demand volume (kg) based on search history and order velocity.
   - `POST /price-trends`: Multi-factor price regression model.
   - `POST /route-optimize`: Direct API wrapper for TSP routing.
   - `GET /market-basket`: Returns Apriori frequent itemsets and cross-sell rules from MongoDB transaction logs.

8. Farm Tourism & Agritourism (`/api/tours`):
   - `GET /farmer/:id`: Lists available farm tour slots.
   - `POST /book`: Books agritourism visit with group size and advance fee payment.
   - `GET /customer/:id`: Customer's booked farm visits.
   - `PUT /booking/:id/status`: Farmer confirms or cancels booking.

9. Escrow Payments (`/api/payment`):
   - `POST /create-razorpay-order`: Initializes payment order on Razorpay servers; returns `order_id`.
   - `POST /verify-payment`: Validates Razorpay HMAC-SHA256 signature against `RAZORPAY_KEY_SECRET`.

15. DEVELOPER-LEVEL ENGINEERING BLUEPRINT & WORKFLOWS
================================================================================

1. Architectural Design Patterns:
   - Service-Repository Pattern: Business logic is decoupled from Express route handlers into dedicated service files (`trustScoreService.js`, `deliveryRouteService.js`, `demandPredictionService.js`), ensuring testability and separation of concerns.
   - Observer / Pub-Sub Pattern: Socket.io handles event-driven pub-sub communication across clients and servers.
   - Strategy Pattern: Dynamic pricing adapts algorithm strategies based on data availability (ML XGBoost regression -> Gaussian heuristic fallback).
   - Middleware Pipeline: Express intercepts requests sequentially (Helmet -> RateLimiter -> MongoSanitize -> DOMPurifySanitizer -> JWTAuth -> RoleRBAC).

2. State Machine Transitions:
   - Escrow Funds Lifecycle:
     [Held in Escrow on Checkout]
          │
          ▼
     [Delivery Completed & Verified via Gemini Vision]
          │
          ├─────────────────────────┬─────────────────────────┐
          ▼                         ▼                         ▼
     [Released to Farmer]    [Disputed by Customer]     [Refunded to Customer]

   - Order Status Lifecycle:
     [Pending] -> [Confirmed] -> [Assigned] -> [Picked Up] -> [In Transit] -> [Delivered]
          │             │            │
          └─────────────┴────────────┴─────────────> [Cancelled / Refunded]

   - Soil Testing Lifecycle:
     [Pending Assignment] -> [Team Assigned] -> [Sample Collected] -> [Lab Testing] -> [Report Published]

3. Database Concurrency & Race Conditions:
   - Stock Deduction: When an order is placed, stock deduction is executed atomically using MongoDB `$inc`:
     `await Crop.findOneAndUpdate({ _id: cropId, quantity: { $gte: orderedQty } }, { $inc: { quantity: -orderedQty } })`
     If the query returns null, the stock was insufficient, preventing overselling in high-concurrency flash sales.
   - Live Auction Bidding: Bids are validated against `currentHighestBid` in a single atomic transaction to avoid race conditions between simultaneous bidders.

4. Database Indexing Strategy:
   - Geospatial Index: `User.geoPosition` indexed with `2dsphere` for rapid Haversine radial agent queries.
   - Text Search Index: `Crop.name` indexed with `text` for partial keyword matching.
   - TTL Auto-Purge Index: `SearchHistory.createdAt` indexed with `expires: "30d"` to automatically remove queries older than 30 days.
   - Compound Indexes: `{ farmer: 1, status: 1 }` on `Order` for fast farmer dashboard queries.

   - TC-ORDER-02: Multi-location checkout with 3 distinct addresses -> Expect 3 linked Orders under one `multiLocationGroupId` and Delivery created with 3 dropoff waypoints.
   - TC-LOG-01: Agent runs TSP route optimization -> Expect waypoints sorted in minimal distance order with pickups before dropoffs.
   - TC-LOG-02: Agent uploads photo at delivery -> Expect Gemini Vision verification to return `match` or `mismatch`.
   - TC-CLEAR-01: Farmer clicks "Sell to Admin" for perishable crop -> Expect crop ownership assigned to admin, 40% discount applied, `isAdminStock: true`.
   - TC-BROAD-01: Admin broadcasts push advisory -> Expect Socket.io event `admin_broadcast_received` received by connected farmer sockets.
   - TC-SEASON-01: Customer requests seasonal prediction with valid lat/lng -> Expect Open-Meteo weather telemetry, agro-climatic zone classification, and scored crop cards (0-100%).

   - Scenario B: External Weather API Timeout -> Verify `getSeasonalPrediction` falls back to agro-climatic zone defaults without crashing.
   - Scenario C: Socket.io Disconnect -> Verify frontend automatically attempts reconnection with exponential backoff.
